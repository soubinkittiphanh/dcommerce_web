# ສັນຍາການບໍລິການ ແລະ ນຳໃຊ້ຊອບແວ POS ຮ້ານອາຫານ

ສັນຍາສະບັບນີ້ ຖືກເຮັດຂຶ້ນໃນວັນທີ _____ ເດືອນ ____________, 2026 (ຕໍ່ໄປນີ້ເອີ້ນວ່າ "ວັນທີມີຜົນສັກສິດ"), ລະຫວ່າງ:

1. **ບໍລິສັດ ດີ-ຄອມເມີຊ ວິສາຫະກິດສ່ວນບຸກຄົນ (D-COMMERCE SOLE CO., LTD)**, ເປັນບໍລິສັດທີ່ຂຶ້ນທະບຽນຖືກຕ້ອງຕາມກົດໝາຍຂອງ ສາທາລະນະລັດ ປະຊາທິປະໄຕ ປະຊາຊົນລາວ, ຕັ້ງຢູ່ [ນະຄອນຫຼວງວຽງຈັນ, ສປປ ລາວ] (ຕໍ່ໄປນີ້ເອີ້ນວ່າ **"ຜູ້ສະໜອງ"**); ແລະ
2. **[ຊື່ໂຮງແຮມ / ນິຕິບຸກຄົນ]**, ເປັນບໍລິສັດທີ່ຂຶ້ນທະບຽນຖືກຕ້ອງຕາມກົດໝາຍຂອງ [ຊື່ປະເທດ], ຕັ້ງຢູ່ [ທີ່ຢູ່ຂອງໂຮງແຮມ] (ຕໍ່ໄປນີ້ເອີ້ນວ່າ **"ຜູ້ໃຊ້ບໍລິການ"** ຫຼື **"ໂຮງແຮມ"**).

ຜູ້ສະໜອງ ແລະ ຜູ້ໃຊ້ບໍລິການ ຕໍ່ໄປນີ້ຈະຮ່ວມກັນເອີ້ນວ່າ "ຄູ່ສັນຍາ" ແລະ ເອີ້ນສະເພາະວ່າ "ຝ່າຍ".

### ເຫດຜົນຂອງການເຮັດສັນຍາ

**ເນື່ອງຈາກວ່າ**, ຜູ້ສະໜອງ ເປັນເຈົ້າຂອງລິຂະສິດ ແລະ ຜູ້ພັດທະນາຊອບແວລະບົບຂາຍໜ້າຮ້ານ (POS), ໂດຍສະເພາະແມ່ນລະບົບ **D-Commerce Restaurant POS** (ລະບົບ POS ສໍາລັບຮ້ານອາຫານ ແລະ ຄາເຟ່); ແລະ

**ເນື່ອງຈາກວ່າ**, ຜູ້ໃຊ້ບໍລິການ ດຳເນີນທຸລະກິດຮ້ານອາຫານ ແລະ ເຄື່ອງດື່ມ ພາຍໃນພື້ນທີ່ຂອງໂຮງແຮມ ແລະ ມີຄວາມປະສົງຈະຂໍຮັບສິດນຳໃຊ້ລະບົບຊອບແວ D-Commerce Restaurant POS, ຈັດຊື້ອຸປະກອນທີ່ກ່ຽວຂ້ອງ, ພ້ອມທັງຮັບບໍລິການຕິດຕັ້ງ ແລະ ບຳລຸງຮັກສາຈາກຜູ້ສະໜອງ;

**ດັ່ງນັ້ນ**, ອີງຕາມຂໍ້ຕົກລົງ ແລະ ເງື່ອນໄຂຕ່າງໆໃນສັນຍາສະບັບນີ້, ທັງສອງຝ່າຍ ຈຶ່ງຕົກລົງເຫັນດີເປັນເອກະພາບ ດັ່ງນີ້:

## 1. ຂອບເຂດການບໍລິການ ແລະ ການອະນຸຍາດນຳໃຊ້ຊອບແວ

### 1.1 ຊອບແວທີ່ໄດ້ຮັບອະນຸຍາດ
ຜູ້ສະໜອງ ອະນຸຍາດໃຫ້ຜູ້ໃຊ້ບໍລິການມີສິດນຳໃຊ້ (License) ຊອບແວ **D-Commerce Restaurant POS** ພາຍໃນພື້ນທີ່ຂອງໂຮງແຮມ. ຄຸນສົມບັດມາດຕະຖານຂອງລະບົບທີ່ຮວມຢູ່ໃນສິດນຳໃຊ້ນີ້ມີດັ່ງນີ້:
*   **ການຈັດການຜັງໂຕະ (Live Table Grid Layout):** ສະແດງຜັງໂຕະພ້ອມສະຖານະແບບ Real-time (ໂຕະວ່າງ - ສີຂຽວ, ໂຕະມີແຂກ - ສີສົ້ມ/ແດງ, ໂຕະຕ້ອງອະນາໄມ - ສີຟ້າ, ໂຕະຖືກຈອງ - ສີຟ້າອ່ອນ).
*   **ການຕ້ອນຮັບ & ເປີດໂຕະ (Seat Customer):** ບັນທຶກການເປີດໂຕະ, ລະບຸຈຳນວນແຂກ ແລະ ຂໍ້ມູນລູກຄ້າ.
*   **ການຈັດການອໍເດີ (Order & Ticket Management):** ຮອງຮັບການຍ້າຍໂຕະ/ຍ້າຍອໍເດີ, ການແຍກບິນຊຳລະເງິນ (Split Bill / Split Checkout) ແລະ ການເປີດບິນແບບບໍ່ມີໂຕະ (Walk-in / Virtual Tickets).
*   **ການຈັດການສາງ ແລະ ສະຕັອກ (Inventory & Stock Management):** ຕິດຕາມສະຕັອກແບບ Real-time, ແຈ້ງເຕືອນສະຕັອກຂັ້ນຕ່ຳ (minStock) ແລະ ປັບປຸງສະຕັອກແບບກຸ່ມ (Bulk Adjustment).
*   **ລະບົບບັນຊີ ແລະ ໃບລາຍງານກຳໄລ-ຂາດທຶນ (Profit & Loss Reporting):** ສ້າງໃບລາຍງານ P&L ອັດຕະໂນມັດ, ວິເຄາະສັດສ່ວນຕົ້ນທຶນ (Revenue, COGS, OPEX) ແລະ ແຜນວາດວົງມົນ (Donut Chart).
*   **ການເຊື່ອມຕໍ່ສອງໜ້າຈໍ (Dual Customer Screen Sync):** ຊິ້ງຂໍ້ມູນການຂາຍ ແລະ QR Code ສໍາລັບການຊຳລະເງິນໄປຍັງໜ້າຈໍທີສອງຂອງລູກຄ້າ.

### 1.2 ຮູບແບບການຕິດຕັ້ງ ແລະ ຄວາມຮັບຜິດຊອບດ້ານຂໍ້ມູນ
ຜູ້ໃຊ້ບໍລິການ ຕົກລົງເລືອກຮູບແບບການຕິດຕັ້ງລະບົບ ດັ່ງຕໍ່ໄປນີ້:

*   [ ] **ແບບລະບົບ Cloud (Online Version):** ຜູ້ສະໜອງ ເປັນຜູ້ຈັດການລະບົບ Server ພາຍນອກ ແລະ ສຳຮອງຂໍ້ມູນ (Backup) ໃຫ້. ຜູ້ສະໜອງຮັບຜິດຊອບໃນການເກັບຮັກສາຄວາມປອດໄພຂອງຂໍ້ມູນ ແລະ ຄວາມພ້ອມໃນການເຂົ້າເຖິງລະບົບ.
*   [ ] **ແບບລະບົບ Offline (Offline Version):** ຊອບແວຈະຖືກຕິດຕັ້ງລົງໃນເຄື່ອງຄອມພິວເຕີພາຍໃນຂອງຜູ້ໃຊ້ບໍລິການໂດຍກົງ. ຜູ້ໃຊ້ບໍລິການຕ້ອງຮັບຜິດຊອບໃນການຈັດການຂໍ້ມູນທັງໝົດດ້ວຍຕົນເອງ, ລວມທັງການສຳຮອງຂໍ້ມູນ (Backup) ແລະ ຄວາມປອດໄພ. ຜູ້ສະໜອງຈະບໍ່ຮັບຜິດຊອບຕໍ່ການສູນເສຍຂໍ້ມູນ ທີ່ເກີດຈາກເຄື່ອງເພ, ເຄື່ອງເສຍ, ລະບົບປະຕິບັດການຂັດຂ້ອງ ຫຼື ການລຶບຂໍ້ມູນໂດຍບັງເອີນໃນແບບ Offline.

## 2. ຄ່າບໍລິການ ແລະ ເງື່ອນໄຂການຊຳລະເງິນ

### 2.1 ຄ່າທຳນຽມລະບົບ ແລະ ບໍລິການ
ຜູ້ໃຊ້ບໍລິການ ຕົກລົງຊຳລະຄ່າບໍລິການຕາມທີ່ລະບຸໄວ້ໃນ **ເອກະສານແນບ ກ (ຕາຕະລາງລາຄາ)** ເຊິ່ງປະກອບມີ:
1.  **ຄ່າອະນຸຍາດນຳໃຊ້ຊອບແວ (License Fees):** [ລະບຸເປັນລາຍເດືອນ, ລາຍປີ ຫຼື ແບບຊື້ຂາດ].
2.  **ຄ່າບໍລິການຕິດຕັ້ງ ແລະ ເຝິກອົບຮົມ (Setup & Training Fees):** ຄ່າຕິດຕັ້ງລະບົບ, ການຕັ້ງຄ່າຖານຂໍ້ມູນ ແລະ ການເຝິກອົບຮົມພະນັກງານ.
3.  **ຄ່າອຸປະກອນ (Hardware Fees):** ຄ່າເຄື່ອງ POS, ເຄື່ອງພິມໃບບິນ, ກ່ອງເກັບເງິນ ແລະ ເຄື່ອງອ່ານບັດ NFC.

### 2.2 ການຊຳລະເງິນ ແລະ ການລະງັບບໍລິການ
*   ສໍາລັບຜູ້ໃຊ້ບໍລິການແບບ Cloud ຕ້ອງຊຳລະຄ່າບໍລິການລ່ວງໜ້າຕາມກຳນົດເພື່ອຮັກສາສິດການເຂົ້າເຖິງຂໍ້ມູນ.
*   **ການຊຳລະຊ້າ:** ຫາກຊຳລະຊ້າເກີນ ເຈັດ (7) ວັນ ນັບຈາກວັນຄົບກຳນົດ, ຜູ້ສະໜອງ ມີສິດລະງັບການເຊື່ອມຕໍ່ລະບົບ Cloud, ລະງັບການຊິ້ງຂໍ້ມູນ ແລະ ປິດການເຂົ້າໃຊ້ງານຊົ່ວຄາວ ໂດຍບໍ່ຕ້ອງຮັບຜິດຊອບຕໍ່ຄວາມເສຍຫາຍໃດໆ ທາງທຸລະກິດຂອງຜູ້ໃຊ້ບໍລິການ.

## 3. ການຮັບປະກັນອຸປະກອນ (Hardware Warranty)

### 3.1 ການຮັບປະກັນ
ໃນກໍລະນີທີ່ຜູ້ໃຊ້ບໍລິການ ຈັດຊື້ອຸປະກອນຮາດແວໂດຍກົງຈາກຜູ້ສະໜອງ, ຜູ້ສະໜອງຮັບປະກັນວ່າຮາດແວດັ່ງກ່າວຈະບໍ່ມີຄວາມບົກພ່ອງຈາກການຜະລິດ ພາຍໃຕ້ການນຳໃຊ້ປົກກະຕິ.

### 3.2 ໄລຍະເວລາຮັບປະກັນ
ຜູ້ສະໜອງ ຮັບປະກັນອຸປະກອນເປັນເວລາ **ໜຶ່ງ (1) ປີ** ນັບຈາກວັນທີ່ສົ່ງມອບອຸປະກອນ.

### 3.3 ເງື່ອນໄຂ ແລະ ຂໍ້ຍົກເວັ້ນ
*   **ຂອບເຂດການຮັບປະກັນ:** ຮັບປະກັນສະເພາະຄວາມຜິດພາດ ຫຼື ຄວາມເສຍຫາຍ ທີ່ເກີດຈາກຂະບວນການຜະລິດເທົ່ານັ້ນ.
*   **ຂໍ້ຍົກເວັ້ນ (ການຮັບປະກັນສິ້ນສຸດລົງທັນທີ):** ການຮັບປະກັນຈະບໍ່ກວມເອົາ ແລະ ຈະສິ້ນສຸດລົງທັນທີ ຫາກອຸປະກອນເປ່ເພຍ້ອນ:
    1.  ການຕົກເຮ່ຍ, ແຕກຫັກ ຫຼື ຖືກກະທົບຢ່າງແຮງຈາກປັດໄຈພາຍນອກ.
    2.  ຖືກນ້ຳ, ເຄື່ອງດື່ມ, ຄວາມຊຸ່ມ ຫຼື ທາດແຫຼວຕ່າງໆ.
    3.  ໄຟຟ້າລັດວົງຈອນ, ໄຟຕົກ, ໄຟເກີນ ຫຼື ລະບົບໄຟຟ້າບໍ່ສະຖຽນ.
    4.  ການດັດແກ້, ແກ້ໄຂ ຫຼື ຖອດເຄື່ອງໂດຍບຸກຄົນອື່ນທີ່ບໍ່ແມ່ນພະນັກງານຂອງຜູ້ສະໜອງ.

## 4. ການເຮັດວຽກຂອງລະບົບ ແລະ ການປັບແຕ່ງເພີ່ມເຕີມ

### 4.1 ຄຸນສົມບັດມາດຕະຖານ
ຜູ້ໃຊ້ບໍລິການ ຕົກລົງວ່າໄດ້ກວດກາ ແລະ ຍອມຮັບຄຸນສົມບັດການເຮັດວຽກມາດຕະຖານຂອງລະບົບ (Standard Functionality) ສໍາລັບ Restaurant POS (ທີ່ລະບຸໄວ້ໃນ ໜ້າລາຍລະອຽດການເຮັດວຽກຂອງລະບົບ `/admin/system-details`) ແລ້ວ.

### 4.2 ການປັບແຕ່ງນອກເໜືອມາດຕະຖານ
ຫາກຜູ້ໃຊ້ບໍລິການ ມີຄວາມຕ້ອງການເພີ່ມເຕີມ, ດັດແກ້ ຫຼື ປັບແຕ່ງລະບົບ ນອກເໜືອຈາກຄຸນສົມບັດມາດຕະຖານເຫຼົ່ານີ້, ຈະມີການຄິດໄລ່ຄ່າບໍລິການ ແລະ ຄ່າພັດທະນາເພີ່ມເຕີມ ຕາມອັດຕາຊົ່ວໂມງ ຫຼື ຕາມການປະເມີນຕົວຈິງຂອງຜູ້ສະໜອງ.

---

## 5. ການເຊື່ອມຕໍ່ລະບົບພາຍນອກ ແລະ ຂໍ້ຈຳກັດຄວາມຮັບຜິດຊອບກ່ຽວກັບ API ຂອງທະນາຄານ

### 5.1 ການເຊື່ອມຕໍ່ລະບົບຊຳລະເງິນ
ຊອບແວນີ້ຮອງຮັບການເຊື່ອມຕໍ່ກັບ API ຂອງທະນາຄານ (ເຊັ່ນ: ທະນາຄານ ຮ່ວມທຸລະກິດ ລາວ-ຫວຽດ / LVB) ເພື່ອສ້າງ Dynamic QR Code ໃນການຊຳລະເງິນ ແລະ ກວດສອບທຸລະກຳແບບ Cashless.

### 5.2 ຄວາມຮັບຜິດຊອບ ແລະ ລະບົບຂັດຂ້ອງ
*   ເນື່ອງຈາກການບໍລິການເຫຼົ່ານີ້ ຂຶ້ນກັບເຄືອຂ່າຍອິນເຕີເນັດພາຍນອກ ແລະ ໂຄງສ້າງລະບົບ API ຂອງທະນາຄານເອງ, ຜູ້ສະໜອງ ຈະບໍ່ຮັບຜິດຊອບຕໍ່ຄວາມຊັກຊ້າໃນການຊຳລະເງິນ, ຄວາມຫຼົ້ມເຫຼວໃນການສ້າງ QR Code, ບັນຫາເຄືອຂ່າຍຂັດຂ້ອງ (timeout) ຫຼື ທຸລະກຳທີ່ບໍ່ສຳເລັດ ທີ່ເກີດຈາກລະບົບ API ຫຼື Server ຂອງທະນາຄານ.
*   ຜູ້ໃຊ້ບໍລິການ ຕົກລົງທີ່ຈະບໍ່ຮ້ອງຮຽນ, ຟ້ອງຮ້ອງ ຫຼື ຮຽກຮ້ອງຄ່າເສຍຫາຍໃດໆ ມາຍັງຜູ້ສະໜອງ ສໍາລັບຄວາມເສຍຫາຍທາງການເງິນ, ການເສຍໂອກາດທາງການຄ້າ ຫຼື ຄວາມຜິດພາດຂອງທຸລະກຳ ທີ່ເກີດຈາກບັນຫາລະບົບ API ຂອງທະນາຄານຂັດຂ້ອງ ຫຼື ຢຸດເຮັດວຽກ.

## 6. ນະໂຍບາຍການນຳໃຊ້ບັດ NFC ແລະ ການຊຳລະເງິນ (ຫາກມີການນຳໃຊ້)

ໃນກໍລະນີທີ່ໂຮງແຮມນຳໃຊ້ລະບົບບັດ NFC ສໍາລັບແຂກພັກ ຫຼື ພະນັກງານ:
1.  **ການອອກບັດ:** ໂຮງແຮມ ເປັນຜູ້ຮັບຜິດຊອບໃນການອອກບັດ ແລະ ຈັດການບັດ NFC.
2.  **ບັດເສຍ:** ຜູ້ສະໜອງ ຈະບໍ່ຮັບຜິດຊອບຕໍ່ຍອດເງິນທີ່ເຫຼືອ ຫຼື ຂໍ້ມູນທີ່ສູນເສຍ ຍ້ອນບັດເສຍ, ຖືກລັກ ຫຼື ບັດຊຳລຸດ.
3.  **ການຮັກສາບັດ:** ໂຮງແຮມ ຕ້ອງແນະນຳໃຫ້ຜູ້ຖືບັດຫຼີກເວັ້ນການຫັກງໍ, ເຈາະຮູ ຫຼື ວາງບັດໄວ້ບ່ອນທີ່ມີຄວາມຮ້ອນສູງ/ແມ່ເຫຼັກ.
4.  **ການກວດສອບຕົວຕົນ:** ໂຮງແຮມ ມີໜ້າທີ່ກວດສອບຕົວຕົນຂອງຜູ້ຖືບັດ. ຜູ້ສະໜອງ ຈະບໍ່ຮັບຜິດຊອບຕໍ່ທຸລະກຳທີ່ເກີດຂຶ້ນຈາກບັດທີ່ຖືກລັກ ຫຼື ນຳໃຊ້ໂດຍບຸກຄົນອື່ນໂດຍບໍ່ໄດ້ຮັບອະນຸຍາດ.

---

## 7. ການຮັກສາຄວາມລັບ ແລະ ຄວາມປອດໄພຂອງຂໍ້ມູນ

ຄູ່ສັນຍາທັງສອງຝ່າຍ ຕົກລົງທີ່ຈະຮັກສາຄວາມລັບ ແລະ ບໍ່ເປີດເຜີຍຂໍ້ມູນທາງທຸລະກິດ, ຂໍ້ມູນທາງເຕັກນິກ ຫຼື ຂໍ້ມູນລູກຄ້າຂອງອີກຝ່າຍໃຫ້ແກ່ບຸກຄົນພາຍນອກ. ຂໍ້ມູນທຸລະກຳການຂາຍທັງໝົດເປັນກຳມະສິດຂອງໂຮງແຮມ, ແຕ່ລິຂະສິດ ແລະ ຊັບສິນທາງປັນຍາຂອງຊອບແວຍັງເປັນຂອງຜູ້ສະໜອງແຕ່ພຽງຜູ້ດຽວ.

---

## 8. ໄລຍະເວລາສັນຍາ ແລະ ການຍົກເລີກສັນຍາ

*   **ໄລຍະເວລາສັນຍາ:** ສັນຍາສະບັບນີ້ມີກຳນົດເວລາ [ລະບຸໄລຍະເວລາ ເຊັ່ນ: 1 ປີ] ນັບຈາກວັນທີມີຜົນສັກສິດ ແລະ ຈະຖືກຕໍ່ສັນຍາໂດຍອັດຕະໂນມັດ ເວັ້ນເສຍແຕ່ຝ່າຍໃດຝ່າຍໜຶ່ງຈະແຈ້ງເປັນລາຍລັກອັກສອນກ່ອນ ສາມສິບ (30) ວັນ ວ່າບໍ່ປະສົງຈະຕໍ່ສັນຍາ.
*   **ການຍົກເລີກສັນຍາ:** ຝ່າຍໃດຝ່າຍໜຶ່ງມີສິດຍົກເລີກສັນຍາສະບັບນີ້ໄດ້ທັນທີ ຫາກອີກຝ່າຍໜຶ່ງລະເມີດຂໍ້ຕົກລົງໃນສັນຍາ ແລະ ບໍ່ແກ້ໄຂໃຫ້ຖືກຕ້ອງພາຍໃນ ສິບຫ້າ (15) ວັນ ນັບຈາກວັນທີ່ໄດ້ຮັບໃບແຈ້ງເຕືອນ.

## 9. ກົດໝາຍທີ່ນຳໃຊ້ ແລະ ການແກ້ໄຂຂໍ້ຂັດແຍ່ງ

ສັນຍາສະບັບນີ້ ໃຫ້ຢູ່ພາຍໃຕ້ການຄຸ້ມຄອງ ແລະ ຕີຄວາມໝາຍຕາມກົດໝາຍຂອງ ສາທາລະນະລັດ ປະຊາທິປະໄຕ ປະຊາຊົນລາວ. ຫາກມີຂໍ້ຂັດແຍ່ງໃດໆເກີດຂຶ້ນ, ຄູ່ສັນຍາຈະຮ່ວມກັນແກ້ໄຂດ້ວຍການປະນີປະນອມ, ຫາກບໍ່ສາມາດຕົກລົງກັນໄດ້ ແມ່ນໃຫ້ນຳສະເໜີຕໍ່ສານທີ່ມີສິດອຳນາດຢູ່ ນະຄອນຫຼວງວຽງຈັນ ເພື່ອຕັດສິນຕາມຂັ້ນຕອນກົດໝາຍ.

---
