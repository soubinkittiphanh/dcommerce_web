# ສັນຍາການຮ່ວມມື, ການຈັດຊື້ລະບົບ POS ແລະ ການເຊື່ອມຕໍ່ລະບົບຊຳລະເງິນ

ສັນຍາສະບັບນີ້ ຖືກເຮັດຂຶ້ນໃນວັນທີ _____ ເດືອນ ____________, 2026 (ຕໍ່ໄປນີ້ເອີ້ນວ່າ "ວັນທີມີຜົນສັກສິດ"), ລະຫວ່າງ:

1. **ບໍລິສັດ ດີ-ຄອມເມີຊ ວິສາຫະກິດສ່ວນບຸກຄົນ (D-COMMERCE SOLE CO., LTD)**, ເປັນບໍລິສັດທີ່ຂຶ້ນທະບຽນຖືກຕ້ອງຕາມກົດໝາຍຂອງ ສາທາລະນະລັດ ປະຊາທິປະໄຕ ປະຊາຊົນລາວ, ຕັ້ງຢູ່ [ນະຄອນຫຼວງວຽງຈັນ, ສປປ ລາວ] (ຕໍ່ໄປນີ້ເອີ້ນວ່າ **"D-Commerce"**); ແລະ
2. **ທະນາຄານ ຮ່ວມທຸລະກິດ ລາວ-ຫວຽດ (LAO-VIET JOINT VENTURE BANK)**, ເປັນສະຖາບັນການເງິນທີ່ໄດ້ຮັບອະນຸຍາດດຳເນີນທຸລະກິດຖືກຕ້ອງຕາມກົດໝາຍຂອງ ສາທາລະນະລັດ ປະຊາທິປະໄຕ ປະຊາຊົນລາວ, ຕັ້ງຢູ່ສຳນັກງານໃຫຍ່ [ທີ່ຢູ່ນະຄອນຫຼວງວຽງຈັນ, ສປປ ລາວ] (ຕໍ່ໄປນີ້ເອີ້ນວ່າ **"ທະນາຄານ"** ຫຼື **"LVB"**).

D-Commerce ແລະ ທະນາຄານ ຕໍ່ໄປນີ້ຈະຮ່ວມກັນເອີ້ນວ່າ "ຄູ່ສັນຍາ" ແລະ ເອີ້ນສະເພາະວ່າ "ຝ່າຍ".

### ເຫດຜົນຂອງການເຮັດສັນຍາ

**ເນື່ອງຈາກວ່າ**, D-Commerce ເປັນຜູ້ພັດທະນາ ແລະ ຈຳໜ່າຍລະບົບຊອບແວ POS (Minimart POS ແລະ Restaurant POS) ພ້ອມທັງສະໜອງອຸປະກອນຮາດແວ POS ທີ່ກ່ຽວຂ້ອງ; ແລະ

**ເນື່ອງຈາກວ່າ**, ທະນາຄານ ໃຫ້ບໍລິການຮັບຊຳລະເງິນ, ລະບົບສ້າງ QR Code ໃນການຊຳລະເງິນ ແລະ ບໍລິການທາງການເງິນອື່ນໆ ຜ່ານລະບົບ Open API ຂອງທະນາຄານ (ຕໍ່ໄປນີ້ເອີ້ນວ່າ "ບໍລິການ Gateway"); ແລະ

**ເນື່ອງຈາກວ່າ**, ທະນາຄານ ມີຄວາມປະສົງຈະຈັດຊື້ລະບົບ POS (ຊອບແວ ແລະ ຮາດແວ) ຈາກ D-Commerce ເພື່ອໄປແຈກຢາຍ ຫຼື ຊ່ວຍເຫຼືອ (Subsidize) ໃຫ້ແກ່ລູກຄ້າຮ້ານຄ້າຂອງທະນາຄານ (Merchants) ເພື່ອສົ່ງເສີມການເປີດບັນຊີ ແລະ ເພີ່ມຍອດທຸລະກຳຜ່ານທະນາຄານ; ແລະ

**ເນື່ອງຈາກວ່າ**, D-Commerce ຕົກລົງທີ່ຈະເຊື່ອມຕໍ່ລະບົບ Open API ຂອງທະນາຄານ ເຂົ້າກັບລະບົບ POS ເພື່ອໃຫ້ຮ້ານຄ້າທີ່ຮ່ວມລາຍການສາມາດສ້າງ Dynamic QR Code ໃນການຮັບຊຳລະເງິນຢູ່ໜ້າຈໍ POS ແລະ ເງິນຈະຖືກໂອນເຂົ້າບັນຊີທະນາຄານ LVB ຂອງຮ້ານຄ້າໂດຍກົງ;

**ດັ່ງນັ້ນ**, ທັງສອງຝ່າຍ ຈຶ່ງຕົກລົງເຫັນດີເປັນເອກະພາບ ດັ່ງນີ້:

## ໝວດທີ I: ແຜນງານການຈັດຊື້ລະບົບ POS

### 1. ການຈັດຊື້ລະບົບ POS
ທະນາຄານ ຕົກລົງຈັດຊື້ ແລະ D-Commerce ຕົກລົງສະໜອງລະບົບ POS ເຊິ່ງປະກອບມີ:
*   **ລິຂະສິດນຳໃຊ້ຊອບແວ D-Commerce POS** (ແບບ Cloud-Based ຫຼື Offline ຕາມທີ່ຕົກລົງ).
*   **ຊຸດອຸປະກອນຮາດແວ POS** (ເຄື່ອງ POS ໜ້າຈໍສຳຜັດ, ເຄື່ອງພິມໃບບິນ 80mm, ກ່ອງເກັບເງິນ ແລະ ເຄື່ອງອ່ານບັດ NFC).

### 2. ການແຈກຢາຍ ແລະ ຕິດຕັ້ງໃຫ້ຮ້ານຄ້າ
*   **ຮ້ານຄ້າເປົ້າໝາຍ:** ທະນາຄານ ຈະເປັນຜູ້ກຳນົດ ແລະ ອະນຸມັດລາຍຊື່ຮ້ານຄ້າ ("ຮ້ານຄ້າຮ່ວມລາຍການ") ທີ່ຈະໄດ້ຮັບລະບົບ POS ພາຍໃຕ້ການຊ່ວຍເຫຼືອຂອງທະນາຄານ.
*   **ການຕິດຕັ້ງ ແລະ ເຝິກອົບຮົມ:** D-Commerce ຈະຮັບຜິດຊອບໃນການຕິດຕັ້ງຊອບແວ, ຮາດແວ, ການຕັ້ງຄ່າຖານຂໍ້ມູນ ແລະ ການເຝິກອົບຮົມພະນັກງານຂອງຮ້ານຄ້າຢູ່ສະຖານທີ່ຈິງ.
*   **ໄລຍະເວລາສົ່ງມອບ:** D-Commerce ຈະດຳເນີນການຕິດຕັ້ງພາຍໃນ [ລະບຸ 7-10 ວັນ] ລັດຖະການ ນັບຈາກວັນທີ່ໄດ້ຮັບການຢືນຢັນລາຍຊື່ຮ້ານຄ້າ ແລະ ຂໍ້ມູນຈາກທະນາຄານ.

### 3. ລາຄາ ແລະ ການຊຳລະເງິນໃຫ້ D-Commerce
*   ລາຄາຂອງຊອບແວ ແລະ ຮາດແວ ແມ່ນລະບຸໄວ້ໃນ **ເອກະສານແນບ ກ (ລາຄາລະບົບ POS)**.
*   ທະນາຄານ ຈະຊຳລະເງິນໃຫ້ D-Commerce ໂດຍກົງເປັນລາຍ [ເດືອນ / ໄຕມາດ] ອີງຕາມໃບບິນຮຽກເກັບເງິນ ຫຼັງຈາກທີ່ໄດ້ຕິດຕັ້ງ ແລະ ມີການເຊັນຮັບມອບລະບົບຈາກຮ້ານຄ້າແລ້ວ.
*   ຮ້ານຄ້າຮ່ວມລາຍການ ຈະບໍ່ຖືກຮຽກເກັບຄ່າລະບົບ ຫຼື ຄ່າອຸປະກອນຈາກ D-Commerce (ເວັ້ນເສຍແຕ່ຮ້ານຄ້າຕ້ອງການອຸປະກອນ ຫຼື ບໍລິການປັບແຕ່ງລະບົບນອກເໜືອຂໍ້ຕົກລົງ).

## ໝວດທີ II: ການເຊື່ອມຕໍ່ລະບົບຊຳລະເງິນ (LVB OPEN API)

### 4. ຂອບເຂດການເຊື່ອມຕໍ່ທາງເຕັກນິກ
D-Commerce ຈະດຳເນີນການເຊື່ອມຕໍ່ API ຂອງທະນາຄານ LVB ເຂົ້າກັບລະບົບ POS ໂດຍມີລາຍລະອຽດດັ່ງນີ້:
1.  **ການສ້າງທຸລະກຳ (Init API):**
    *   Endpoint: `https://laovietbank.com.la:5678/v1/api/init/`
    *   ໜ້າທີ່: ສ້າງ Dynamic QR Code ໃນໜ້າຈໍ POS ເພື່ອໃຫ້ລູກຄ້າສະແກນຈ່າຍ.
    *   ຂໍ້ມູນທີ່ສົ່ງ: `Service_Id`, `Merchant_Id`, `Merchant_Name`, `Trandate`, `Trans_Id`, `Trans_Desc`, `Amount`, `Curr`, `Payer_Id`, `Payer_Name`, `Payer_Addr`, `Type`, `Custmer_Id`, `Customer_Name`, `IssueDate`, `Callback_URL` ແລະ `Secure_Code`.
2.  **ການເຂົ້າສູ່ລະບົບ (Login API):**
    *   Endpoint: `https://laovietbank.com.la:5678/v1/api/login`
    *   ໜ້າທີ່: ຂໍສິດ Bearer Token ສໍາລັບການກວດສອບທຸລະກຳ.
3.  **ການກວດສອບສະຖານະທຸລະກຳ (Transaction Check API):**
    *   Endpoint: `/v1/api/provider/transaction` ແລະ `/v1/api/provider/transaction/{Trans_Id}`
    *   ໜ້າທີ່: ກວດສອບສະຖານະການຊຳລະເງິນໃນກໍລະນີທີ່ລະບົບ Callback ຊັກຊ້າ.

### 5. ການສ້າງລາຍເຊັນ Secure Code & ຄວາມປອດໄພ
ເພື່ອປ້ອງກັນການປອມແປງທຸລະກຳ, ຂໍ້ມູນການຮ້ອງຂໍທັງໝົດຈະຕ້ອງຖືກລົງລາຍເຊັນດິຈິຕອນ ໂດຍການໃຊ້ MD5:
*   **ຮູບແບບການ Hash:** 
    `MD5(privateKey | Service_Id | Merchant_Id | Merchant_Name | Trandate | Trans_Id | Trans_Desc | Amount | Curr | Payer_Id | Payer_Name | Payer_Addr | Type | Custmer_Id | Customer_Name | IssueDate | Callback_URL)`
*   **ການປົກປ້ອງຄີ:** ທັງສອງຝ່າຍ ຕົກລົງທີ່ຈະເກັບຮັກສາ `privateKey` ໄວ້ເປັນຄວາມລັບສູງສຸດ ແລະ ເຂົ້າລະຫັດໄວ້ຢ່າງປອດໄພ. ທະນາຄານມີໜ້າທີ່ຮັບຜິດຊອບໃນການປ່ຽນຄີ ແລະ ແຈ້ງ D-Commerce ລ່ວງໜ້າເປັນລາຍລັກອັກສອນ.

### 6. ການສົ່ງຂໍ້ມູນການຊຳລະເງິນກັບຄືນ (Callback / Webhook)
*   **Callback URL:** D-Commerce ຈະຈັດຕັ້ງ Endpoint ທີ່ປອດໄພເພື່ອຮັບການແຈ້ງເຕືອນການຊຳລະເງິນສຳເລັດຈາກທະນາຄານ.
*   **ການກວດສອບ:** ເມື່ອໄດ້ຮັບຂໍ້ມູນ Callback, ລະບົບຂອງ D-Commerce ຈະກວດສອບ `Secure_Code` ກ່ອນຈະປ່ຽນສະຖານະໃນ POS ວ່າ "ຈ່າຍແລ້ວ" ແລະ ພິມໃບບິນ.
*   **ການສົ່ງຄືນຂໍ້ມູນຄືນໃໝ່:** ລະບົບຂອງທະນາຄານ ຈະຕ້ອງພະຍາຍາມສົ່ງ Callback ຢ່າງໜ້ອຍ [ລະບຸ 3 ຄັ້ງ] ຫາກພົບວ່າເຄືອຂ່າຍມີບັນຫາຂັດຂ້ອງຊົ່ວຄາວ.

### 7. ຄວາມພ້ອມຂອງລະບົບ API, SLA ແລະ ຂໍ້ຈຳກັດຄວາມຮັບຜິດຊອບ
*   **SLA ຂອງທະນາຄານ:** ທະນາຄານ ຮັບຜິດຊອບໃນການຮັກສາສະຖຽນລະພາບ ແລະ ຄວາມພ້ອມໃຊ້ງານຂອງລະບົບ Open API (`laovietbank.com.la`). ທະນາຄານຮັບປະກັນຄວາມພ້ອມໃຊ້ງານຂອງ API ບໍ່ຕ່ຳກວ່າ [ລະບຸ 99.5%] ໃນຊ່ວງເວລາການດຳເນີນທຸລະກິດ.
*   **ຂໍ້ຈຳກັດຄວາມຮັບຜິດຊອບ:** D-Commerce ຈະບໍ່ຮັບຜິດຊອບຕໍ່ຄວາມລົ້ມເຫຼວໃນການຊຳລະເງິນ, ຄວາມຊັກຊ້າ ຫຼື ຄວາມຜິດພາດໃນການສ້າງ QR Code ທີ່ເກີດຈາກລະບົບ API ຂອງທະນາຄານຢຸດເຮັດວຽກ ຫຼື ຂັດຂ້ອງ.
*   **ການກວດສອບ ແລະ ປຽບທຽບຍອດ:** ທະນາຄານ ຮັບຜິດຊອບໃນການປຽບທຽບຍອດເງິນຂັ້ນສຸດທ້າຍ. ຫາກມີຂໍ້ຜິດພາດ (ເຊັ່ນ: ລະບົບ POS ບອກວ່າບໍ່ໄດ້ຮັບເງິນ ແຕ່ບັນຊີລູກຄ້າຖືກຕັດເງິນ), ໃຫ້ຖືເອົາບັນທຶກທຸລະກຳ (Transaction Log) ຂອງທະນາຄານເປັນຫຼັກ ແລະ ທະນາຄານຈະແກ້ໄຂບັນຫາຮ່ວມກັບລູກຄ້າ ແລະ ຮ້ານຄ້າໂດຍກົງ.

### 8. ຄ່າທຳນຽມທຸລະກຳ ແລະ ສ່ວນແບ່ງລາຍຮັບ (ຫາກມີ)
*   ຄ່າທຳນຽມການຮັບຊຳລະເງິນຜ່ານ QR (MDR) ທີ່ຮ້ານຄ້າຕ້ອງຊຳລະໃຫ້ທະນາຄານ ແມ່ນ [ລະບຸ ___%].
*   **ສ່ວນແບ່ງລາຍຮັບ:** [ຫາກມີ, ລະບຸສ່ວນແບ່ງລາຍຮັບທີ່ທະນາຄານຈະແບ່ງໃຫ້ D-Commerce ເຊັ່ນ: "ທະນາຄານ ຕົກລົງແບ່ງສ່ວນແບ່ງຄ່າທຳນຽມ MDR ໃຫ້ D-Commerce ຈຳນວນ ____% ຫຼື ຈ່າຍຄ່າຄອມມິດຊັນ ____ ກີບ ຕໍ່ທຸລະກຳ"].

## ໝວດທີ III: ຂໍ້ກຳນົດທົ່ວໄປ

### 9. ການຮັບປະກັນອຸປະກອນ
D-Commerce ຮັບປະກັນອຸປະກອນຮາດແວທີ່ສະໜອງໃຫ້ເປັນເວລາ **ໜຶ່ງ (1) ປີ**. ການຮັບປະກັນຈະສິ້ນສຸດລົງທັນທີ ຫາກອຸປະກອນເສຍຫາຍຈາກການຕົກເຮ່ຍ, ຖືກນ້ຳ, ໄຟຟ້າລັດວົງຈອນ ຫຼື ການແກ້ໄຂດັດແປງໂດຍບໍ່ໄດ້ຮັບອະນຸຍາດ.

### 10. ການຮັກສາຄວາມລັບ
ຂໍ້ມູນການຊຳລະເງິນ, API Key, Token ແລະ ຂໍ້ມູນທຸລະກຳທັງໝົດຂອງຮ້ານຄ້າ ແລະ ລູກຄ້າ ຖືເປັນຄວາມລັບສູງສຸດ. ທັງສອງຝ່າຍຈະຕ້ອງປະຕິບັດຕາມມາດຕະຖານຄວາມປອດໄພທາງໄຊເບີເພື່ອປ້ອງກັນຂໍ້ມູນຮົ່ວໄຫຼ.

### 11. ໄລຍະເວລາ ແລະ ການສິ້ນສຸດສັນຍາ
*   ສັນຍາສະບັບນີ້ມີກຳນົດເວລາ **ສອງ (2) ປີ** ນັບຈາກວັນທີມີຜົນສັກສິດ.
*   ຝ່າຍໃດຝ່າຍໜຶ່ງມີສິດຍົກເລີກສັນຍາໄດ້ໂດຍການແຈ້ງເປັນລາຍລັກອັກສອນລ່ວງໜ້າ ເກົ້າສິບ (90) ວັນ. ໃນກໍລະນີສິ້ນສຸດສັນຍາ, D-Commerce ຈະຍັງຄົງໃຫ້ບໍລິການ ແລະ ສະໜັບສະໜູນຮ້ານຄ້າທີ່ໄດ້ຕິດຕັ້ງໄປແລ້ວຕໍ່ໄປ, ແລະ ທະນາຄານຕ້ອງຊຳລະຄ່າບໍລິການທັງໝົດທີ່ຍັງຄ້າງຈ່າຍໃຫ້ D-Commerce.

### 12. ກົດໝາຍທີ່ນຳໃຊ້
ສັນຍາສະບັບນີ້ ໃຫ້ຢູ່ພາຍໃຕ້ການຄຸ້ມຄອງ ແລະ ຕີຄວາມໝາຍຕາມກົດໝາຍຂອງ ສາທາລະນະລັດ ປະຊາທິປະໄຕ ປະຊາຊົນລາວ.
